# Версионируемые проверки GIS-очередей

Статус: ограниченное выделение проверок 2026-10-06 для будущего авторства. Текущая очередь не переключена.

В `scripts/gis-queue-checks/` сохранена логика проверок из
`queues/gis-terminal-accepted-continuation-20261006/`. Каталог локальных
доказательств теперь передаётся явно, вместо вычисления относительно скрипта.
Старые файлы сохранены без изменений: действующие и исторические manifests,
команды и хеши продолжают ссылаться на них.

Это специализированный контракт той линии продолжения, а не проверка любой
GIS-очереди: gate сохраняет требования к 77 пакетам исходного manifest,
source-gate — к 17 принятым пакетам, launch-readiness — к конкретному виду
двухзадачной закрытой приёмки. Новая очередь с другим контрактом требует
отдельного изменения проверки и тестов, а не ослабления ожидаемых значений.

## Входы и команды

Запускать из корня Orchestrator; путь каталога доказательств абсолютный.
Пример формы Windows machine gate (подставить фактический каталог при авторстве):

```text
node scripts/gis-queue-checks/gate.mjs --evidence-dir "C:\absolute\evidence" after q1000-041-b
node scripts/gis-queue-checks/source-gate.mjs --evidence-dir "C:\absolute\evidence"
node scripts/gis-queue-checks/launch-readiness.mjs --evidence-dir "C:\absolute\evidence"
```

`gate.mjs` поддерживает прежние `plan`, `before`, `after`, `prefix`, `final`
и использует manifest, preflight, исходные snapshots и block-файлы из выбранного
каталога. `source-gate.mjs` читает source-binding и manifest.
`launch-readiness.mjs` читает deployment-binding, pilot-acceptance и manifest;
вызывает проверки по точным путям, заданным bindings. Они могут оставаться
локальными, поэтому эта поставка кода не делает частные доказательства
переносимыми. Запуск разрешён только с доверенным заранее проверенным binding.

Проверки не создают новых очередей, receipts или run-записей. Они завершаются
ошибкой при отсутствии входов, несовпадении хешей или нарушении утверждений.
Не запускать проверки текущего меняющегося состояния параллельно публикации.

## Проверка выделения

```text
node --test scripts/gis-queue-checks/checks.test.mjs
```

Тесты проверяют обязательный абсолютный каталог, сохранение phase/batch,
положительные и отрицательные условия двух candidate-профилей, footprint
остальных профилей и source-gate на изолированных fixtures с 17 пакетами,
включая отклонение изменённого доказательства. Проверки `gate` и
`launch-readiness` по живым доказательствам активной очереди не запускались.

## Последующая привязка

После завершения текущего run при авторстве следующей очереди явно включить
эти versioned scripts в её механическую привязку, передать каталог evidence,
перепроверить весь контракт и выполнить preflight. Не редактировать для этого
старые manifests, YAML или canonical records. Исторические одноразовые
подготовительные скрипты и private evidence остаются в `queues/`; они не входят
в поставку повторно используемых проверок.
